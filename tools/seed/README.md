# 社区种子数据(本地演示用)

> ⚠️ **这批账号的口令是公开写在本文档里的**(下面那张表)。它们只适用于**本地演示**。
> 如果你哪天把这个站部署到公网,**先把这批账号删掉或改掉口令** —— 否则任何人都能用
> `haitang / demo1234` 登录并在你的站上发文章。
> 清理命令一条就够:`mysql -uroot -p blog_sys < tools/seed/clear.sql`。

这个目录把一份「像真的有人在用的博客社区」灌进数据库:14 个账号、8 篇已发布文章、
1 篇草稿、40 多条评论(带两级回复)、若干点赞与收藏,以及分布在过去六个月里的浏览量与时间线。

## 怎么用

```bash
# 1. 先看它打算做什么(默认 dry-run,只读不写,连清理都不做)
node tools/seed/seed.mjs

# 2. 真写:先清后插
node tools/seed/seed.mjs --apply

# 3. 重跑时复用上次上传的图,省掉三分钟出图
node tools/seed/seed.mjs --apply --skip-images
```

前提:后端在 `http://localhost:8080` 上跑着(可用 `community.json` 的 `baseUrl` 改),
本机有 `mysql` 客户端。出图需要本机 ComfyUI(`imggen` 技能,端口 8888);
不想出图就加 `--skip-images`。出图脚本默认按 `~/.dsh/skills/imggen/gen.py` 找(不写死任何机器与用户名),装在别处时用 `IMGGEN` 环境变量指定。

清理(独立于脚本,随时可以手动跑):

```bash
mysql -uroot -p blog_sys < tools/seed/clear.sql
```

## 三条安全阀

1. **默认不写**。不加 `--apply`,脚本只打印计划与一份只读的计数(将要删除多少行)。
2. **只碰名单上的账号**。清理与写入的边界都是 `community.json` 里的用户名清单;
   你原有的 4 个账号(`admin` / `zzkk` / `alice` / `bob`)与 5 篇文章不在名单里,
   脚本会在动手前后各核对一次,数量变了就报错退出。
3. **同一份名单只有一个真源**。`clear.sql` 里那份用户名清单必须与 `community.json`
   完全一致,不一致脚本直接报错 —— 否则一次改动就会让清理漏删或误删。

两条**有意为之**的连带删除(删除前会打印计数):种子文章下的所有评论都会被删(包括不是
种子账号写的 —— 文章本身要没了,留下孤儿评论行更脏);清理后**没有任何文章引用**的标签
会被删掉(仍被真实文章使用的标签一律不动)。

## 为什么走接口而不是直接写 SQL

计数列(`like_count` / `comment_count` / `view_count`)是应用自己维护的。手写 INSERT
很容易造出「点赞数 38、点赞记录只有 6 条」这种**会撒谎的数据** —— 而假数据最要紧的品质
恰恰是不能撒谎。走接口则由构造保证一致:点赞走点赞接口,评论走评论接口,浏览量靠真实
调用详情接口累加。

唯一一件接口做不到的事是**发布时间回填**(创建时间由服务端取当前时间),所以最后用一条
`UPDATE articles SET created_at=...` 把时间线挪到设计好的时间点上。浏览量与时间线是
「模拟出来的效果」,其余全是真实行为留下的行。
