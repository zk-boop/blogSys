站点的 Markdown 渲染器上线那天,配置文件一共 11 行。三天之后它变成 60 多行,因为我忍不住把能开的语法全开了一遍。再往后一周,我又伸手回去关掉了三个。

判断标准只有一条:这个语法是给"写给自己看的笔记"用的,还是给"发给别人读的文章"用的。前者我基本全开,后者只留真正会出现在正文里的。按这条标准过一遍,结论比我预想的干脆:

| 语法 | 现在开着吗 | 关掉它我失去了什么 | 我的判断 |
|---|---|---|---|
| 表格 | 开着 | 一年少写十来篇方案对比 | 手机上会挤,但值得 |
| 任务列表 | 开着 | 读者没法把我的清单抄回去用 | 复制出去还能看出进度 |
| 删除线 | 开着 | 少一种"我改过主意"的说法 | 用得比想象中多 |
| 脚注 | 关了 | 读书笔记那种补充说明没地方放 | 手机上来回跳的成本太高 |
| 数学公式 | 关了 | 一年两篇的公式只能贴图片 | 为两篇多加载一个渲染包不划算 |
| 正文里的原生 HTML | 关了 | 老文章的特殊排版得改写 | 安全和排版都得我自己兜 |

表格是我犹豫最久的一个。竖线在手机窄屏上会挤成一条缝,后来给表格外层加了横向滚动才算能用。真正让我留下它的是写作本身:一张对比表顶得上八百字,读者也省事。代价是我得手工对齐源文件里的竖线,不对齐自己看着难受。

脚注是最舍不得的。我在别处写读书笔记,几乎每页都有脚注,一层不够就用两层。可博客的读者大多在手机上看,点一下跳到底部,再点一下跳回来,来回两趟就把我刚才那句话丢在脑后了。我自己看别人的脚注文章也从不点,承认这一点之后,砍掉它就没那么难。代价是有一篇讲版本号的文章,括号套了三层,读起来像绕口令,后来我把它整篇重写了一遍。

任务列表原本以为用不上,直到我发现有人把我的清单整段复制走当模板。`- [x]` 复制到别的编辑器里,至少还能看出哪几条已经做完,这比好看重要。

删除线留得很坚决。我用它标记"这里我改过主意了":把"我打算每周写一篇"划掉,改成"我打算每月写一篇"。出版物不会留这种痕迹,博客可以,这是它比纸有意思的地方之一。

搭渲染器的时候我给自己列过一张单子,做完一条打一个勾:

- [x] 表格
- [x] 任务列表
- [x] 删除线
- [x] 代码高亮与语言标注
- [ ] 脚注
- [ ] 数学公式
- [ ] 正文里插原生 HTML

打勾的四样里,代码高亮最费时间。渲染这边交给 highlight.js,首屏一下子多了六十多 KB,一个只写随笔的站点背这个包实在浪费。后来改成按语言懒加载,只有正文里出现代码块才去取对应的语法文件。做完之后我用手机流量测了一遍,首页省下来的那一秒,比什么功能都值。

还有几个开关是"半开"的,记下来免得自己以后忘了为什么:

- 自动识别链接
  - 关掉了。有一次正文里写了个文件路径,它把斜杠后面那截认成了网址,页面上凭空多出一条蓝色下划线的 404。
  - 但显式写出来的完整链接我保留,否则引用来源得手打尖括号。
- 换行即分段
  - 开着。我写东西习惯一段一行,关掉之后连自己预览都要愣一下。
- 目录
  - 自己生成,没用渲染器管。踩过的坑是中文标题做锚点会被编码成一长串百分号,复制给人很难看,所以给每个标题算了个短标识。

现在配置又回到了 11 行。偶尔还是会想念脚注,尤其写读书笔记的时候。但一想到读者可能正举着手机,在晃来晃去的地铁上读我写的东西,就不想念了。
