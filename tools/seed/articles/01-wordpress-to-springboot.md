2016 年 3 月,我在一台年付两百六的共享主机上装了 WordPress。理由很朴素,主题多、插件多、不用写代码。八年之后回头看,那套东西长成了 23 个插件、480MB 的数据库,以及十几个我自己都忘了用途的自定义字段。

把它推到临界点的是一次升级。主机商把 PHP 从 7.4 升到 8.1,我那个用了六年的主题在后台直接白屏。我翻开 functions.php,发现里面大半代码是这些年从各种教程里抄的,现在没有一段读得懂。凌晨三点我把版本切回 7.4,第二天开始认真琢磨自己写一个。

算过账才下的决心。主机一年两百六,两个付费插件加起来一百四,这就四百了;而家里那台闲置的小主机一直空着,电费我当没看见。真正让我下决心的不是钱,是我发现自己已经不敢动那个站了 —— 改一行 CSS 都要先备份,因为不知道会连带崩掉什么。

迁移前我列过一张清单,写清楚哪些东西非有不可:草稿箱、标签、站内搜索、评论、RSS、图片上传。可以砍掉的也写了一列:相册、友情链接、文章归档页、那个用来显示天气的小挂件。清单一共 21 行,后来真正做完的是 17 行,剩下的 4 行里有 3 行是砍掉的,1 行是我忘了。

新站是 Spring Boot 3.4 配 MySQL 8,本机 JDK 17。选它不是因为时髦,是我白天上班就写 Java,半夜排查问题不想再学一套东西。前端 Vue 3,Markdown 交给 markdown-it。架子搭起来只用了两个周末,真正耗时的是把八年的数据搬过来。

导出反而是最省事的。老库还在主机上,整库 dump 下来,在自己机器上还原成一个叫 `wp_old` 的库,和新库并排放着:

```bash
mysqldump -u blog -p \
  --single-transaction \
  --default-character-set=utf8mb4 \
  wp_blog > wp_blog_20240117.sql

mysql -uroot -p -e "CREATE DATABASE wp_old DEFAULT CHARSET utf8mb4"
mysql -uroot -p wp_old < wp_blog_20240117.sql
```

导入我写了个只在本地跑的一次性任务,用 `CommandLineRunner` 挂在启动流程里,一个新库一个旧库,两个 `JdbcTemplate` 各连一头:

```java
@Override
public void run(String... args) {
    String sql = """
            SELECT ID, post_title, post_name, post_content, post_date
            FROM wp_old.wp_posts
            WHERE post_type = 'post'
              AND post_status IN ('publish', 'draft')
            """;
    List<OldPost> olds = oldJdbc.query(sql, (rs, i) -> new OldPost(
            rs.getLong("ID"),
            rs.getString("post_title"),
            rs.getString("post_name"),
            rs.getString("post_content"),
            rs.getTimestamp("post_date").toLocalDateTime()));
    olds.forEach(importer::save);
}
```

`save` 那个方法里塞了转换、去重、写新表三件事,写到后面全是补丁,不好意思贴出来,但它确实能跑。

这个任务我跑了三次。第一次跑完发现标签全丢了,因为我漏了 `wp_term_relationships`;第二次跑到一半抛异常,新库里躺了八百多篇半截文章,只好 `DROP DATABASE blog_sys` 重建。第三次跑之前我先把导入逻辑拆成两段,先纯读旧库写到一张临时表,确认数量对得上再进正式表。

动手导库之前,我还拿旧库做了一轮灰度验证:把 1,834 篇文章全部跑一遍渲染,不落库,只看输出。这一步翻出 6 篇正文里还带着 `<font color="red">` 的老文章,还有一篇整段包在 `<marquee>` 里 —— 那是我 2016 年刚建站时觉得特别酷的效果。这 6 篇我手工改了两篇,剩下 4 篇留着,现在从列表页点进去还能看见红字,像考古。

那天晚上日志刷得很快。04:12 结束,一共 1,834 篇文章、9,127 条评论、31,204 条被标记为垃圾的评论、4,015 条附件记录,整个过程 26 分钟。

数据搬完不等于搬对。下面这几个坑,每一个我都是几天之后才发现的。

最麻烦的是时区。`wp_posts` 里存了两套时间:`post_date` 是站点本地时间,`post_date_gmt` 是 UTC,而当年到底谁往哪边写,取决于那年我装的是哪个插件。我图省事直接取了 `post_date_gmt`,结果 2013 到 2015 年那批文章在页面上全部早了八小时 —— 凌晨一点发的,显示成前一天下午五点。后来我用了个笨办法:两列差值刚好等于 8 小时的,信 `post_date`;不相等的挑出来手工核对,806 篇里挑出 41 篇,花了我一个晚上,其中 3 篇我自己也记不清到底是几点发的,就随手写了个中午。

评论表也不听话。`comment_parent` 允许无限层嵌套,我那几年攒出了五级的楼中楼,而新站只做两级,回复一律挂在一级评论下。我写了一段往上找祖先的递归,把深层的评论挂到最顶上那条。顺手做的事还有一件:我把 `comment_author_url` 直接扔了。后果是七八条老评论失去了当年指向对方博客的地址,现在读起来像自言自语。其中有一条是 2015 年一个陌生人写的"我会一直看你的",没了链接,那句话突然变得很轻。

正文更乱。`post_content` 里存的不是 Markdown,是 HTML 混着短代码。我数了一下,一共 6 种:`[caption]`、`[gallery]`、`[audio]`,还有三个只有原作者自己知道的插件语法。能转的转成 Markdown,转不了的 217 篇保留原始 HTML,我在渲染器上开了 `html: true` 放行。代价是站内搜索的摘要里会漏出尖括号。不完美,先这样,等哪天有空再回来啃。

字符集那事我到现在还有点介意。老库是 `utf8mb3`,我当年在手机上发的几条带表情的短记,其实在旧站上就已经是问号了,只是我自己从没点开看过。迁移前我把这些问号统一替换成了省略号。八年的残缺,最后被一条 `UPDATE` 抹平。

图片是另一笔账。附件路径要靠 `_wp_attached_file` 拼上 uploads 目录,而 2017 年之前我图省事用外链图床,那个图床 2019 年就关门了。213 张图现在还是灰色小方块,我没有去修,只在文章底下加了一行说明。摘要当年是靠 `<!--more-->` 切的,新站改成正文前 120 字,读起来少了一口气,我又写了个脚本把标签前后的内容重新拼回去。

老地址也得管。旧站的链接是 `/archives/1234` 这种形式,我一开始只想做一层 rewrite 全部 301 到新地址,结果搜索引擎那边还是掉了一波收录。后来干脆在新站加了个 `legacy_id` 字段,把旧 ID 存下来,访问老链接时查一次再跳转。这个字段现在唯一的用处就是这个,但它值。

标签我是趁这次一起收拾的。`wp_terms` 里躺着 312 个标签,一半只用过一次,还有 mysql、MySQL、mysql5.7 这种明显该合并的。最后压到 84 个。合并的时候我按文章数排了个序,发现用得最多的那个标签是"随笔",112 篇 —— 我写了八年,最常干的事还是随便说说。

评论里还有个我自己造的麻烦。导入时我按邮箱匹配用户,结果有几个当年换过邮箱的老朋友被判成了访客,他们名下的评论显示成匿名。一共 5 个人、60 多条评论,我手工改了回去。改的时候顺手看了内容,有两个人已经五年没出现了。

搜索我推倒重来过一次。第一版用 `LIKE '%关键词%'`,1,800 篇文章下一秒钟都出不来;换成 MySQL 的全文索引,发现中文分词它根本不管你,整句话被当成一个词。最后用的是 ngram 分词,配 `ngram_token_size=2`,搜"慢查询"终于能出东西了。索引重建那天数据库卡了四分钟,我坐在旁边没敢动。

点赞和收藏是新站才有的功能,所以老文章的点赞数全是 0。中间我动过一个歪念头:给老文章填一批随机点赞数,看起来热闹。填了两百多篇之后我自己受不了,全撤了。现在 2016 年那几篇文章底下干干净净,反而挺诚实。

老站还有个访问统计插件,库里存了 12 万条浏览记录。我兴冲冲迁过来,后来发现里面一半是 2019 年那波爬虫留下的,真实数字大概只剩三成。新站干脆不做阅读量,只在前台显示点赞和评论数 —— 少一个每天盯着看的数字,我居然轻松了一点。

部署用的是 Docker Compose,三个容器:MySQL 8、后端、前端 nginx,对外分别映射 3307、8082、8081。切上线第二天早上出了个事故,前端请求 `/api` 前缀没有重写,读者看到的是 404。我当时在开会,拿手机连上去改 nginx 配置,改了十几分钟,手心全是汗。这事让我明白一件事:自己写的系统,没有"等运维来看"这个选项。

备份是每天凌晨三点 `mysqldump` 一份到另一块盘,保留 14 天。这套东西加起来二百多行配置,以前在 WordPress 里是三个插件干的事,而其中一个已经三年没更新过。

切域名是今年 1 月 30 日,一个周六下午。我提前一天把 DNS 的 TTL 调到 300 秒,切完之后盯着日志看了一个钟头。首页从 2.1 秒降到 340 毫秒。这不是因为我写得好,是因为没有 23 个插件互相等对方了。

编辑器我推翻过一次。一开始照着老习惯做了个可视化编辑器,加粗、插图都能点,写完才发现输出的 HTML 里段落套段落,因为换行被当成了新段落,整篇排版全乱。后来只留 Markdown 源码加一块实时预览,左边写字右边看效果。写了两周之后我发现自己打字快了,原因很可能是手不用离开键盘了。

迁移后这一年,我写得反而少了。以前打开后台就能写,现在要先 `npm run dev`,写完还得想着推上去重新构建。每月从四五篇掉到两三篇。但我愿意改了,代码高亮、目录、排版终于是我说了算。

也有丢人的地方。重读旧文章时翻到 2017 年那一批,我通篇自称"笔者",看得脸热。当年觉得这样显得正式。

还有一件忘了做的事:RSS。我一直以为自己不需要,直到有读者发邮件问我是不是停更了,才发现新站根本没有 feed,那份订阅地址空了三个月。垃圾评论倒是从每天 40 条变成了 0,因为我压根没做评论通知 —— 机器人也懒得来。这算好算坏,我说不清。

如果有人问我该不该自己写一个,我的答案取决于一件事:你打算多久之后还看得懂自己的代码。八年前我选 WordPress,是因为不用写代码;八年后我选自己写,是因为想把每一个坑记在自己账上。中间这些年不算浪费,只是绕了一圈。
