# 披露语义：不可见即不存在，写操作一并返回 404

我们决定让可见性模块同时拥有**列表过滤**与**单篇披露**，并且对不可见的单份内容一律以「不存在」响应 —— 包括点赞、收藏、评论这三个写操作。

理由是：「不可见」与「不存在」一旦可以区分，就等于向任何人确认了被封禁内容的存在；而写操作此前能在一篇详情页返回 404 的文章上成功，本身就是同一个判断被漏掉的表现，不是独立的功能。

## Consequences

**这是对外行为变更，不是内部重构。** `POST /api/articles/{id}/like`、`POST /api/articles/{id}/favorite`、`POST /api/articles/{id}/comments` 在「文章存在但作者被封禁」的情况下，会从成功变为 404。前端需要相应处理；不接受 403，因为 403 同样确认了内容的存在。

## Considered Options

- **只做列表过滤**：改动最小，但 `GET /api/articles/{id}/recommend` 与 `/comments` 仍会对一篇 404 的文章返回 200，矛盾原样保留。
- **不可见时返回 403**：语义上更"诚实"，但同样泄露了存在性，等于把问题换个状态码继续存在。
